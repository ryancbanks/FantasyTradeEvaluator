# Weekly source collection contract

The installed application collects each accepted provider once per weekly snapshot and performs all trade enumeration and season simulation locally. It never makes one upstream request per candidate trade. FantasyPros analyzer observations are collected only when FantasyPros power mode is enabled, and then only for the bounded initial/revalidation methodology experiment.

## Supported acquisition paths

### FantasyPros

FantasyPros is optional. When its power mode is enabled, an explicitly paired Chrome/Edge extension operates in the user's ordinary signed-in browser and captures only the response bodies and tables already used by My Playbook. The collector retains semantic league data and sanitized analyzer observations only; it removes request URLs, query strings, cookies, headers, and the league key before persistence. The installed workflow does not require or request a FantasyPros API key, and the extension has no cookie permission. When FantasyPros is off, no FantasyPros page is opened and the app publishes a clearly labeled independent power model instead.

### ESPN

ESPN publishes a signed-in [Complete Projections](https://fantasy.espn.com/football/players/projections) table and defines `PROJ` as its projected score for the upcoming game. No supported public ESPN fantasy-football projections API was found in ESPN's developer documentation. The default connector therefore captures the rendered projection table once, page by page, using the user's normal access; it does not depend on undocumented internal endpoints.

The refresh first attempts exactly two bounded, cookie-free ESPN JSON reads: one league snapshot and one season-level `proTeamSchedules_wl` schedule snapshot. The league read also requests the bounded season transaction ledger; this is not a third request and is never repeated per trade. An explicit access denial enables a signed-in retry inside the extension's already-open scan tab. ESPN's page makes those same credentialed requests, so the browser attaches its session internally; neither cookies nor request headers cross the extension boundary. The extension returns only allowlisted league, roster, scoring, schedule, transaction, and injury fields. A strict parser validates team and game coverage, transactions, byes, and provider context. Pending, failed, canceled, unknown, owner/member, and offer-only data is excluded. ESPN is also a required independent projection publisher.

### Independent public projections

Broad consensus automatically attempts built-in, allowlisted pages from ESPN, CBS Sports, FFToday, and FantasySharks. Users never paste these source URLs; a preview of every safe built-in source path plus the league-bound ESPN addresses is shown under **Automatic source links & debug**. CBS supplies season projections. FFToday supplies weekly QB/RB/WR/TE/K and season QB/RB/WR/TE/K/DL/LB/DB tables; DST and weekly IDP are intentionally excluded because those public rows do not expose stable player identity links. FantasySharks supplies weekly and Rest-of-Year tables for offense, kickers, defense, and IDP. Full-season totals are converted to the verified remaining NFL schedule before use. Each accepted publisher receives one equal vote per player-week, regardless of how many pages, positions, or horizons were captured from it.

FantasyPros and FFA are aggregate products, so they are never averaged with their possible constituent publishers. FantasyPros projections remain available for FantasyPros-style power evidence and become the sole declared forecast fallback only when broad consensus is turned off in FantasyPros mode. FFA is a methodology reference, not a projection vote. Broad consensus requires at least two accepted independent publishers; a rejected best-effort capture contributes no fabricated or zero value.

### Yahoo league projections

Yahoo is a required forecast input. The user supplies one numeric league, team, Players, or Player List link; the app normalizes it to that league's All Players page, verifies reception scoring from the same league's Settings page, and captures weekly and remaining/full-season projection tables through the signed-in browser. Public default and editorial ranks remain reference-only and are never converted into fantasy points.

An ESPN link may be copied from League Home, My Team, Standings, Scoreboard, Schedule, Rosters, Settings, Transactions, or another page inside the ESPN Fantasy Football league. Only one numeric `leagueId` is retained; route, team, week, view, invite, filter, and hash-route state are discarded before the app constructs its own allowlisted ESPN projection and league-data addresses. When FantasyPros provides a linked ESPN ID, the pasted ID must match it. When FantasyPros omits or changes the shape of its ESPN link, the pasted League Home ID supplies the missing identifier and the later roster/team cross-check still fails closed on the wrong league.

## One-pass collection sequence

1. Pair the extension with a one-use, two-minute code approved from the extension popup. The extension opens one temporary scan tab in the user's normal browser profile; it never opens a second collector tab.
2. Discover the team count, every roster, custom starting slots, IR/reserve capacity, standings, completed and remaining matchups, scoring rules, playoff/tiebreak rules, and the complete NFL pro-team schedule from ESPN. When FantasyPros mode is enabled, its signed-in league view is independently cross-checked against ESPN. No team count or player-by-player roster entry is required.
3. When FantasyPros mode is enabled, capture the actual current consensus expert IDs, weekly/remaining-season ECR, player crosswalk, and FantasyPros projection evidence. ECR changes refresh player inputs; they do not refit formula coefficients. Independent mode skips this step.
4. Reuse the same scan tab to capture ESPN and Yahoo, then automatically attempt CBS, FFToday, and FantasySharks when broad consensus is enabled; never keep more than one collector tab open. Closing the app tab, scan tab, or completed session revokes the bridge token and closes the remaining scan tab.
5. Normalize every required provider/player/week cell. A missing or failed row is stored with an explicit status and is never converted to zero.
6. Hash raw response bodies in memory, write sanitized normalized datasets, validate the full provider grid, append sanitized league activity to versioned local SQLite history, then publish the immutable snapshot atomically. Capture records and engine bindings are idempotent and conflict-detecting.
7. In FantasyPros mode, if no validated formula exists—or the public analyzer fingerprint changed—run the bounded power-only calibration experiment: 250 atomic training observations plus 100 leakage-safe blind package observations. The blind design deterministically covers every feasible balanced package size the budget permits and must include 2-for-2, 3-for-3, and 4-for-4. If a compatible exact formula exists, revalidate it on the same scoped design from the current weekly snapshot. Reuse is allowed only when maximum raw score and delta errors are each at most `1e-6` and every displayed change matches; a missing, stale, insufficient, or failed report routes the refresh back through calibration. Independent mode instead builds its documented remaining-points power policy and records an independent disclosure.
8. In FantasyPros mode, exact publication remains the default. An explicit, unchecked-by-default user option may publish a freshly fitted current-week surrogate only when the solver converged, the design is identifiable, training fits within the exact tolerance, and the full diverse blind design ran. The bundle stores a separate content-addressed surrogate disclosure—not an exact attestation—with blind maximum score error, display-match rate, holdout IDs/sizes, and the source fit ID. That fit ID binds the full solver diagnostics checked by the publication gate. A surrogate is never eligible for weekly formula reuse and never replaces the canonical exact formula.
9. Freeze the accepted forecast-provider set and its one-vote-per-publisher rule into the bundle, close the scan tab, and disconnect the short-lived extension session. All later filtering, scenario generation, trade search, standings, playoff analysis, and spreadsheet export remain offline.

The default current-week-only mode captures a weekly table and a rest-of-season or full-season table wherever the publisher safely exposes joinable rows. A publisher may therefore have season-only evidence for a position such as FFToday IDP. Missing future weekly rows are allocated from that publisher's normalized remaining total against the verified NFL schedule. A player is eligible for the local calculation domain only when the configured provider quorum can be materialized without treating missing values as zero. The advanced future-week option requests every remaining week and should be enabled only when the selected sites visibly publish that full range.

## Privacy and freshness

- Browser profiles, cookies, and OAuth tokens remain under the normal browser's control. The extension has no cookie permission and never returns browser storage or credentials to the app. None is exported to Excel or copied into calibration artifacts.
- A capture timestamp records when the app observed a row. A provider publication time is stored separately only when the provider supplies one.
- General Manager Insights stores team-season activity rather than private owner identity. It learns only from verified completed movements. ESPN exposes `proposedDate` on the records used here, not a separately verified execution timestamp, so that proposal time is retained as the lower bound and the first scan containing the completed transaction is used only as a conservative “executed by” upper bound. A historical trade is valued only when a complete transaction capture spans the evidence window and a compatible weekly engine was captured strictly before the proposal time within the contemporaneous weekly window. Overlapping execution windows or intervening participant moves make roster order ambiguous and withhold the valuation; an ambiguous third-team move preserves the two participants' power result but suppresses the league-wide playoff delta. Current revaluation never fills a missing historical value: it re-scores only the identical package in the already reconstructed pre-trade roster context.
- The local history database is not embedded in exported workbooks or portable weekly bundles. It stores a one-way league pseudonym, canonical team/player IDs, successful waiver bids when supplied, roster/lineup/injury-status snapshots, and completed movements. It does not store raw league IDs, member/owner records, cookies, headers, rejected offers, or failed waiver claims.
- Frequency and proposal guidance expose their sample size and uncertainty. “Completed-deal accessibility” means estimated future **completed-trade activity**, never the probability that a particular offer will be accepted. “Counterparty value opportunity” is independently calculated as the negative of the team's exact transaction-time relative power edge; no activity input is blended into it. Current roster compatibility uses no behavior input at all and remains available without history, but its quick exhaustive discovery scope is limited to eligible 1-for-1 swaps and current positional complements. Stingy/generous/even labels are withheld until at least three exact transaction-time valuations exist; approximate valuations remain descriptive, and unavailable old rankings are never replaced with hindsight data.
- A raw then/current comparison remains descriptive. A good/bad foresight alias requires at least three same-context comparisons, exact power methodology at both times, ACTIVE status for every traded player across complete weekly captures no more than eight days apart, and an uncertainty interval outside the neutral band. Captured injuries and insufficient health evidence are excluded rather than counted; IR placement or a missing projection is never treated as medical evidence. Weekly status capture cannot prove that no change occurred between scans, so even an eligible signal is labeled non-causal.
- Snapshot readiness requires the exact content-addressed scoring profile and an explicit row from every configured provider for every computation-domain player and remaining week. The full verified profile is persisted in the portable engine bundle; ID-only legacy bundles fail closed instead of reconstructing settings from a scoring label.
- After collection, the accepted forecast-provider set is frozen into the bundle and validated against that publisher's planned safe horizon coverage. Rejected best-effort publishers contribute no values. Per-player/week quorum checks still reject holes inside an otherwise usable publisher capture; missing rows never become zero. The completion message and workbook provenance name the publishers actually selected. Snapshot readiness also requires the exact content-addressed scoring profile; ID-only legacy bundles fail closed instead of reconstructing settings from a scoring label.
- Weekly materialization uses the separately verified NFL schedule for game context and byes. Source points and raw projected stats are left unchanged; schedule enrichment never invents a player projection.
- A degraded broad ensemble may run only when at least two independent publishers remain accepted and every player-week meets the recorded observed-source quorum. Missing is explicit and never zero; the app never gives a failed capture a synthetic vote.
- Matching FantasyPros client-bundle and response-schema fingerprints are necessary but not sufficient for reuse. Every weekly refresh binds its revalidation report to the saved formula, current methodology fingerprint, and current snapshot; a changed fingerprint or failed weekly holdout gate invalidates reuse until calibration passes again.
- Calibration proof is scoped. The current ordinary-power experiment validates only the balanced `(n, n)` package sizes listed in its content-addressed evidence, with no implicit free-agent addition or roster drop. Imbalanced and add/drop searches must fail closed or be labeled outside the exact FantasyPros scope until a separate explicit analyzer experiment validates those operations.
- Imported or collected surrogate bundles require a second explicit acceptance before combination counting or trade search. All such searches remain offline. Observed balanced/no-adjustment shapes are labeled `surrogate`; unobserved, imbalanced, and add/drop shapes are labeled `surrogate_extrapolated`. Neither label is an exact FantasyPros claim.

## Portable installation target

There is no single binary format that runs on literally every device. The release matrix produces self-contained application installers for Windows 11+, current macOS, and supported Debian/Ubuntu 64-bit Linux, covering x64 and ARM64 where the frozen runtime is validated. Python, Codex, compilers, and developer tools are not prerequisites for those native builds. Weekly collection requires a current desktop Chrome or Edge browser that permits a user-loaded Manifest V3 extension. A separate source bootstrap covers supported desktops that already have Python 3.11+, but it is not a substitute for an OS-native artifact. Mobile operating systems and locked-down devices that forbid extension installation are outside the initial target.
